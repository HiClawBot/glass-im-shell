# Host Readiness

Use this checklist before embedding Glass IM Shell in another project or publishing a package update.

## Embedding

- Host page imports `styles.css` before `script.js`.
- Host page provides a stable root element and uses `surface: "embedded"` unless the shell owns the full viewport.
- Host page controls shell height through `--glass-shell-height` and validates mobile safe-area behavior.
- Host page does not depend on internal class names; tests use `data-glass-*` attributes.
- Host page follows the route, selector, event payload, and data replacement contract in `docs/API_CONTRACT.md`.

## Runtime Control

- Initial route is set through `route`.
- Language is set through `lang` or host locale detection.
- Appearance uses `appearance: "system"` unless the host owns light/dark mode.
- Density is selected deliberately for the host surface.
- Theme changes use `setTheme()` or `configure({ theme })` with documented token names.

## Data Ownership

- Host data follows `schema.d.ts`.
- Mock data remains fictional in public demos.
- Host data override examples in `docs/HOST_DATA_OVERRIDES.md` are reviewed before publishing integration claims.
- User-generated text is escaped or sanitized before entering host-provided data.
- Wallet data is treated as display-only unless the host implements its own secure backend.

## Events

- Host subscribes to `onEvent` for routing, messages, contact actions, wallet actions, and settings actions that need external handling.
- Event handlers tolerate unknown event types for forward compatibility.
- Public API changes are documented in `docs/API_CONTRACT.md`, `INTEGRATION.md`, and `schema.d.ts`.

## Accessibility

- Visible controls have an accessible name through text, `aria-label`, a label, or a title.
- Buttons declare `type` so embedded host forms are not submitted unexpectedly.
- Keyboard focus remains visible.
- Dialog-style sheets keep focus inside the sheet until closed.
- Escape closes an open sheet first, then closes the mobile detail layer.
- Mobile touch targets stay large enough for repeated use.

## Visual Boundary

- No third-party product marks, official screenshots, copied icon files, copied product text, or real public-person likenesses are added.
- Public preview art and screenshots use only `docs/assets/` originals or `output/smoke/` files generated by this repository.
- CSS changes stay scoped to the shell surface.
- Reduced-motion, light mode, dark mode, compact density, mobile preview, and embedded preview are checked.

## Release

- `npm run release:check` passes.
- `npm run smoke:playwright` passes.
- `npm run ci:verify` passes.
- `npm pack --dry-run` includes the intended public files.
- `docs/BETA_READINESS_REPORT.md` is reviewed for readiness evidence, non-goals, no-go conditions, and final release steps.
- `docs/API_CONTRACT.md` is reviewed for runtime methods, route strings, stable selectors, event payloads, and data replacement rules.
- `docs/HUMAN_ACCEPTANCE_ROUTE.md` is reviewed for the compact manual validation route.
- `docs/PRE_RELEASE_ACCEPTANCE.md` is completed for screenshot, mobile flow, wallet, embedded, package, and release-boundary acceptance.
- `docs/PUBLICATION_READINESS.md` is completed for final repository metadata, evidence, and publisher sign-off.
- `docs/SCREENSHOT_ACCEPTANCE_MAP.md` is reviewed for screenshot route, smoke case, automated check, and no-go condition mapping.
- `docs/MAINTAINER_GUIDE.md` is reviewed for release ownership and package boundary expectations.
- `docs/GITHUB_RELEASE_GUIDE.md` is reviewed before the first public repository release.
- `docs/FIRST_COMMIT_MANIFEST.md` is reviewed before the first public repository commit.
- `docs/REPOSITORY_LAUNCH_CHECKLIST.md` is completed before opening the public repository.
- `docs/LOCAL_PREVIEW.md` is reviewed for canonical local preview and mobile deep-page URLs.
- `docs/PACKAGE_METADATA.md` is reviewed for package entry points and final repository URL fields.
- `docs/HOST_DATA_OVERRIDES.md` is reviewed for host-owned data, async provider, runtime replacement, wallet, theme, and empty-state examples.
- `docs/SUPPLY_CHAIN.md` is reviewed for dependency, script, CI, package, and wallet mock boundaries.
- `docs/UI_IMPLEMENTATION_SPEC.md` is reviewed for public contract, host integration expectations, and acceptance gates.
- `docs/PAGE_MATRIX.md` is reviewed for route, host event, and page acceptance expectations.
- `docs/COMPONENT_MATRIX.md` is reviewed for stable component anatomy, selectors, accessibility, and host override expectations.
- `docs/DESIGN_TOKENS.md` is reviewed for host-safe theme, density, surface, material, motion, and embedded token rules.
- `docs/WALLET_IMPLEMENTATION.md` is reviewed for wallet mock boundaries, data fields, asset rows, flow events, fee/risk display, and host handoff expectations.

- `docs/RELEASE_DRAFT.md` is reviewed before creating a public release.
- `README.md`, `INTEGRATION.md`, `ARCHITECTURE.md`, and `CHANGELOG.md` match the shipped behavior.
