# Screenshot Acceptance Map

This map connects generated screenshots to the route, smoke case, automated checks, manual review goals, and no-go conditions for release review.

Run screenshots with:

```bash
npm run smoke:playwright
```

Generated screenshots are written to `output/smoke/`. That directory is ignored by git and should be regenerated from the current repository before release review.

## Acceptance Rules

| Rule | Requirement |
| --- | --- |
| Source | Screenshots must be generated by this repository or hand-authored under `docs/assets/`. |
| Scope | Only screenshots listed in this map should be used for release review. |
| Data | Visible names, messages, balances, files, and media labels must remain fictional. |
| Identity | Screenshots must not show third-party product identity, official icons, official screenshots, copied artwork, or real public-person likenesses. |
| Layout | No screenshot may show clipped primary navigation, horizontal overflow, text overlap, broken focus, blank panes, or collapsed controls. |
| Wallet | Wallet screenshots must clearly remain display-only mock UI and must not imply custody, signing, live balances, or live asset movement. |

## Wallet Regression Coverage

The current smoke runner also includes `mobile-hash-wallet-regression`. It does not create a dedicated screenshot, but it must pass before release.

It checks:

- `#page:pay`
- `#page:payCode`
- `#page:sendCrypto`
- `#page:transfer`
- `#page:swapCrypto`
- Hash route, dataset, runtime state, and mobile detail state alignment.
- Wallet asset row anatomy for home and deep-page selectors.
- Wallet action events: `wallet:asset`, `wallet:receiveAsset`, `wallet:max`, `wallet:contact`, `wallet:swapDirection`.
- Wallet event payload fields and `state.activePage` for those wallet actions.
- Mobile back behavior from a wallet deep page.

## Review Sequence

1. Run `npm run ci:verify`.
2. Open `output/smoke/`.
3. Review each screenshot in the matrix from top to bottom.
4. Compare failures against the no-go column.
5. If any no-go condition appears, fix the UI and rerun `npm run ci:verify`.
6. Do not use stale screenshots from a previous implementation round.

## Release Notes Usage

Use these screenshots only as review evidence or release attachments. Do not package `output/smoke/` in npm artifacts. The package audit must continue to exclude generated screenshots from the tarball.
